## 1. Implementation
- [x] 1.1 temporal projection/override — `executor/eval/temporal_retag.rs` (new): strict-shape, round-trip-verified re-derivation of a tagged temporal from a stored canonical ISO string, wired into `projection/core.rs`'s `PropertyAccess` dispatch and `temporal.rs`'s arithmetic (`is_duration_object`, `is_datetime_string`, `extract_duration_components`, `try_duration_add/subtract/multiply/divide`, `datetime_add_duration`/`datetime_subtract_duration`/`datetime_difference` rewritten to re-derive components once instead of re-parsing via `chrono` format strings that can't round-trip a seconds-omitted rendering). Design decision: re-derive on read (never store the tagged form) — documented in `temporal_retag.rs`'s module doc, including the string/temporal ambiguity trade-off, the arithmetic-operator string-concat trade-off, and the old-format-data comparison-break trade-off.
- [x] 1.2 store round-trip for temporals — canonical rendering bugs fixed (`render_time_of_day` omits zero seconds, `render_offset` renders `Z` for zero offset); `time`/`datetime`/`localtime`/`localdatetime` map constructors read `nanosecond`/`timezone` keys (validated — nanosecond `[0, 999999999]`, timezone numeric-offset/`Z`/`UTC` only, explicit `CypherExecution` errors otherwise); `datetime({...})` defaults to UTC not the host machine's local offset; `duration({...})` reads a `nanoseconds` key and no longer silently drops a negative `days`/`years`/`months`/`weeks` map value (root cause: unary minus now preserves INTEGER typing — `projection/core.rs`'s `UnaryOperator::Minus`); `duration * number`/`duration / number` added (`temporal.rs::scale_duration`); month-rollover clamping added (`temporal.rs::days_in_month`, applied at all 8 year/month-rollover sites, 2 new + 6 legacy `chrono`-format-string copies).
