## 1. Implementation
- [x] 1.1 Accept optional whitespace between `:` and the label identifier in node patterns (`(dur2: Duration2)`); audit relationship-type position for the same gap
  - `parse_labels` (executor/parser/clauses/pattern.rs) now probes past optional
    whitespace for each label colon and restores the position when none follows,
    so `(v : A : B)` works for every colon, not just the first. The call site
    only enters `parse_labels` with a colon already at the cursor, so the probe
    can only ever consume whitespace that precedes a *subsequent* label colon —
    it cannot leak into the following token (`{`, `)`, `,`, `-`).
  - Relationship-type position had the same gap: `parse_types` now skips
    whitespace after the leading colon (`-[r: KNOWS]->`). The `|` alternation
    path already handled whitespace on both sides.
  - The `:$param` dynamic-label/type sentinel sits behind the same colon and is
    covered by both fixes; it still encodes verbatim (`"$label"`) for
    execution-time resolution.
- [x] 1.2 Verify no collateral: `WHERE n:Label` predicates, map literals `{key: value}`, and parameter syntax unaffected; Temporal8[6]'s 9 rows unblock
  - `WHERE n:Label` is an expression-level label predicate parsed by a separate
    path (identifier.rs); map literals go through `parse_property_map`. Both have
    dedicated control tests at unit and integration level — unchanged.
  - Dynamic label/type parameter syntax covered by a new parser unit test and by
    the pre-existing `dynamic_label_read_path` / `dynamic_rel_type_read_path`
    regression suites (10 tests, green).
  - Temporal8[6] unblock confirmed by a full TCK run: `expressions/temporal`
    661 → 670 (+9, exactly the scenario's 9 example rows), 65.8% → 66.7%.
    Overall 1787 → 1800 of 3868 (46.2% → 46.5%). The residual per-category
    deltas (`clauses/return` +2, `return-orderby` +2, `with-orderBy` +1,
    `merge` -1) are inside the documented ±4 run-to-run noise band.
