# Tasks: phase10_thunder-server-migration

## 2. Dispatch bridge
- [x] 2.1 In `protocol/rpc/server.rs` (or new `thunder_dispatch.rs`): `struct NexusDispatch { state }` implementing `thunder::server::Dispatch` with `type Identity` = the authenticated principal (api-key or user identity from the existing auth manager)
  **DONE (2026-07-25).** `struct NexusDispatch { server: Arc<NexusServer>, auth_required: bool }` in `server.rs`. `type Identity = ()` — the RPC port carries no resolved principal through the session; the command tree only reads `Session::is_authenticated()`, which Thunder flips when `authenticate()` succeeds. Simpler than a User identity and matches how `RpcSession` already worked (an AtomicBool).
- [x] 2.2 `dispatch()` delegates to the existing `dispatch::run(state, cmd, args)` command tree unchanged (CYPHER … EXPORT/IMPORT); handle `HELLO`/`PING` semantics consistently with Thunder's pre-auth allowlist
  **DONE.** `dispatch()` rebuilds a per-request `RpcSession` (server Arc + `authenticated = AtomicBool(session.is_authenticated())` + `auth_required` + `session.connection_id()`) and calls `dispatch::run(&rpc, command, args)` — the command catalog is UNCHANGED. Verified against the Thunder `listener.rs` allowlist (AuthCommand+NotUsed): AUTH is driven by `authenticate()` (never reaches dispatch); QUIT closes; **pre-auth PING** is answered by the listener's `builtin_ping`, **post-auth PING** routes to dispatch (admin PING handler, still returns PONG); **HELLO under NotUsed** routes to dispatch (admin HELLO handler still serves — the `hello_returns_server_identity_and_proto_1` integration test passes). The listener enforces NOAUTH before dispatch, so the tree's own `run` NOAUTH gate is now belt-and-suspenders (kept, harmless).
- [x] 2.3 `authenticate()` maps `thunder::server::Credentials::{ApiKey, UserPass, Token, None}` onto the existing auth manager, preserving current `AUTH <key>` / `AUTH <user> <pass>` behavior and `NEXUS_RPC_REQUIRE_AUTH` (use `ListenerConfig.open()` when auth is disabled)
  **DONE.** `ApiKey|Token → verify_api_key(&server, key)`; `UserPass → verify_user_password(&server, u, p)` (root fast-path + rbac + `verify_password`); `None → false`. Those two `admin.rs` fns were refactored from `&RpcSession` to `pub(crate) &NexusServer` so `authenticate()` and the (now-unreachable-via-listener) `AUTH` command handler share ONE copy. Success → `Principal::new("rpc")`, else `AuthError::InvalidCredentials` (→ profile-correct WRONGPASS). `require_auth=false → ListenerConfig::open()`. `auth_required_blocks_cypher_until_successful_auth` integration test passes (NOAUTH before, OK after root/root).
- [x] 2.4 Migrate `dispatch/` modules from `nexus_protocol::rpc::NexusValue` to `thunder::Value` (type alias first, then mechanical rename; arg helpers `arg_str`/`arg_bytes`/`arg_int`/… keep their signatures)
  **DONE (alias, no rename — matches Synap's `SynapValue = thunder::Value`).** `protocol/rpc/mod.rs`: `pub type NexusValue = thunder::Value; pub use thunder::{PUSH_ID, Request, Response};` (dropped the old `nexus_protocol` codec re-exports — the hand-rolled loop that used them is gone). The 8 handler modules + arg helpers keep the `NexusValue` name and their signatures unchanged. Only Bytes needed touching: `thunder::Value::Bytes` is `Arc<[u8]>` (not `Vec<u8>`), so `arg_bytes` (`b.to_vec()`) and `convert.rs` (`String::from_utf8(b.to_vec())`) + ~9 `#[cfg(test)]` `Bytes(vec!)` → `Value::bytes(vec!)` sites. nexus-server lib 524/0.
